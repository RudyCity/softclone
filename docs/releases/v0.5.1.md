# SoftClone v0.5.1 — Zoom Workplace multi-instance fix

Fixes the report that Zoom profile 1 and profile 2 launched only one Windows desktop window.

## What changed

- `Zoom.exe` on Windows now uses Zoom's **documented multi-instance launch arguments**: `--multipt=TRUE` and `--data=data<instance UUID>`.
- Different SoftClone instances generate different stable Zoom data selectors even if they share the same installed Zoom executable.
- Existing profile records receive the new launch arguments automatically; **you do not need to recreate them**.
- Zoom no longer receives rewritten Windows APPDATA/LOCALAPPDATA values; its vendor-documented `--data` parameter takes responsibility for instance separation.
- The UI now explains Zoom support and distinguishes an application launch request from a confirmed second GUI window.
- Added Windows-specific adapter tests for separate UUIDs and stable launch arguments.

## How to verify on Windows

1. Exit the original Zoom app fully, including its system-tray process.
2. Download and run this SoftClone v0.5.1 build.
3. Open **My clones**, then Launch your existing Zoom profile 1 and Zoom profile 2 separately.
4. Confirm two Zoom windows are visible and sign into separate accounts as needed.

Zoom documents this method in its [developer guide](https://developers.zoom.us/docs/zoom-apps/guides/testing/). The installed Zoom version or organization policies can affect behavior. Automated tests verify the launch arguments but **do not replace an actual Windows GUI test**.

## Other platforms and limits

The Zoom-specific adapter is Windows only. The Zoom developer guide uses separate application bundles on macOS; this update does not automate those installations. It does not bypass Zoom's license, account policies or OS isolation restrictions.
